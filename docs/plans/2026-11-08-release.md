# Releaseflöde: implementationsplan

> **För agenter:** använd superpowers:subagent-driven-development eller superpowers:executing-plans. Stegen har kryssrutor (`- [ ]`).

**Mål:** En merge av release-PR:en på `main` ger tagg, GitHub Release och, efter Jespers godkännande, ett bygge i TestFlight.

**Arkitektur:** En workflow, `.github/workflows/release.yml`, med två jobb. `release-please` körs vid push till `main`. `testflight` körs bara när en release skapades, eller för hand med en tagg, i miljön `testflight`. Versionen ligger i `iOS/Config/Version.xcconfig`.

**Teknik:** GitHub Actions, `googleapis/release-please-action` v5 (låst på SHA), Xcode 26.6 på `macos-26`, `xcodebuild archive` och `-exportArchive` med en App Store Connect API-nyckel.

**Spec:** `docs/specs/2026-11-08-release.md`

## Globala krav

- Svenska i kommentarer, steg-namn och commits. Conventional Commits utan AI-attribution.
- Alla actions låses på en commit-SHA med versionen som kommentar, som i `ios.yml`.
- Hemligheterna heter `ASC_KEY_ID`, `ASC_ISSUER_ID` och `ASC_KEY_P8` (base64), och finns bara i miljön `testflight`.
- Inget steg skriver ut hemliga värden, och inget steg kör `set -x`.
- Byggnummer: `github.run_number` × 100 + `github.run_attempt`.
- Första releasen blir 1.0.0.

## Beslut från förstudien (2026-11-08)

- **Nyckelns roll.** Molnhanterad distributionssignering med `-allowProvisioningUpdates` kräver enligt Apples forum en API-nyckel med rollen **Admin**. Med App Manager eller Developer blir felet "Cloud signing permission error". Det finns ingen Apple-dokumentation som säger annat. Alternativet är manuell signering, med ett distributionscertifikat (.p12 och lösenord) och en profil som fler hemligheter. Det ger fler hemligheter att rotera, men nyckeln kan då ha rollen App Manager. **Jesper valde Admin-nyckeln (2026-11-08).** Den skyddas av att den bara finns i miljön `testflight` med obligatoriskt godkännande.

## Granskningsfokus

1. En release-PR som ändrar `version.txt` men inte `Version.xcconfig`: appens version och taggen går isär. Kontrollera att båda ändras i release-PR:en.
2. En omkörning av TestFlight-jobbet: byggnumret ska öka och inte krocka med ett tidigare.
3. En körning på en fork eller en PR: jobbet `testflight` ska aldrig starta och aldrig komma åt hemligheterna.
4. Ett fel i uppladdningen: nyckelfilen ska ändå tas bort, och arkivet sparas för felsökning.
5. Lokala byggen och `ios.yml` ska fungera som förut efter bytet till `$(MARKETING_VERSION)`.

### Steg 1: Versionen i en egen fil

**Filer:** skapa `iOS/Config/Version.xcconfig`. Ändra `iOS/project.yml`, `iOS/Sophamtning/Info.plist`, `iOS/SophamtningWidgets/Info.plist`, och generera om `iOS/Sophamtning.xcodeproj`.

- [ ] `iOS/Config/Version.xcconfig` innehåller `MARKETING_VERSION = 0.9.0 // x-release-please-version` och `CURRENT_PROJECT_VERSION = 1`. Release Please höjer till 1.0.0 vid första releasen.
- [ ] `project.yml` har `configFiles` för Debug och Release i projektet som pekar på filen, så att alla mål får värdena. Ta bort alla fasta versionsvärden i målen.
- [ ] Båda `Info.plist` använder `$(MARKETING_VERSION)` och `$(CURRENT_PROJECT_VERSION)`.
- [ ] `cd iOS && xcodegen generate`. Bygg och kontrollera att det byggda programmets `Info.plist` har `CFBundleShortVersionString` 0.9.0 och `CFBundleVersion` 1 (`/usr/libexec/PlistBuddy -c Print …`), både i appen och i widgeten. Ett avvikande värde mellan app och widget avvisas av App Store Connect.
- [ ] `swift test` och UI-testerna går igenom.
- [ ] Commit: `build: Appens version läses från Version.xcconfig`

### Steg 2: Release Please

**Filer:** skapa `release-please-config.json`, `.release-please-manifest.json`, `version.txt` och `.github/workflows/release.yml` (bara jobbet `release-please` i det här steget).

- [ ] Konfiguration: `release-type` `simple`, `"release-as": "1.0.0"`, `include-component-in-tag: false` (taggen blir `v1.0.0`), och `extra-files` med `{ "type": "generic", "path": "iOS/Config/Version.xcconfig" }`. Changelogens avsnitt är på svenska: `feat` "Nytt", `fix` "Rättat", `perf` "Snabbare", och dolda typer för resten.
- [ ] Manifestet: `{ ".": "0.9.0" }`. `version.txt` innehåller `0.9.0`.
- [ ] Workflowen körs `on: push: branches: [main]` och `workflow_dispatch` (input `tag`). Behörigheter: `contents: write` och `pull-requests: write` för jobbet. Steget har `id: release`. Jobbets outputs är `release_created` och `tag_name`.
- [ ] Kontrollera med `actionlint`, om det finns, eller med `gh workflow view` efter push, att filen är giltig.
- [ ] Commit: `ci: Release Please håller en release-PR med version och changelog`

### Steg 3: TestFlight-jobbet

**Filer:** ändra `.github/workflows/release.yml`. Skapa `iOS/ExportOptions.plist`.

- [ ] Jobbet `testflight` har `needs: release-please` och körs `if: needs.release-please.outputs.release_created == 'true' || github.event_name == 'workflow_dispatch'`. Det har `environment: testflight`, `runs-on: macos-26`, `timeout-minutes: 45` och `permissions: contents: read`.
- [ ] Checkout av taggen (output `tag_name`, eller input `tag` vid manuell körning). Välj Xcode 26.6. Kör paketets tester, även med `TZ=America/New_York`.
- [ ] Nyckeln skrivs med `echo "$ASC_KEY_P8" | base64 --decode > "$RUNNER_TEMP/AuthKey.p8"` från `env:`, aldrig interpolerat i skriptet.
- [ ] `xcodebuild archive -project iOS/Sophamtning.xcodeproj -scheme Sophamtning -configuration Release -destination generic/platform=iOS -archivePath "$RUNNER_TEMP/Sophamtning.xcarchive" -allowProvisioningUpdates -authenticationKeyPath … -authenticationKeyID … -authenticationKeyIssuerID … CURRENT_PROJECT_VERSION=<beräknat>`
- [ ] `xcodebuild -exportArchive -archivePath … -exportOptionsPlist iOS/ExportOptions.plist -exportPath "$RUNNER_TEMP/export" -allowProvisioningUpdates` med samma nyckelflaggor. `ExportOptions.plist` har `method` `app-store-connect`, `destination` `upload`, `teamID` `4WZU5V58ZG` och `signingStyle` `automatic`.
- [ ] Steget `if: always()` tar bort `AuthKey.p8`. Arkivet laddas upp som artefakt (`actions/upload-artifact`, låst på SHA, `retention-days: 30`), även när uppladdningen fallerar.
- [ ] Commit: `ci: TestFlight-jobbet bygger, signerar och laddar upp efter godkännande`
